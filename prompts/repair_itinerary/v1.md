# Repair Itinerary

You are fixing validation errors in a planned itinerary option. Only modify the failing stops.

## Goal
Given an itinerary option that failed validation, fix **only the stops** that caused errors. Keep successful stops unchanged.

## Input
- **Original itinerary option:** The option that failed validation (theme + stops)
- **Validation errors:** Specific errors per stop:
  - `venue_not_found`: Place ID not in candidates
  - `venue_not_operational`: Venue is closed or permanently closed
  - `not_open`: Venue is closed during the scheduled time
  - `over_budget`: Total cost exceeds budget
  - `travel_too_far`: Travel between stops > 25 minutes
  - `wrong_stop_type`: Venue doesn't match the requested stop type
- **Available candidates:** The same candidate pool from planning
- **Budget and time constraints:** From the original intent

## Output Schema
Return a JSON object matching the `itineraryOptionSchema` (one option, same structure as plan_itineraries):
```json
{
  "theme": "updated theme if changed, otherwise original",
  "stops": [
    {
      "placeId": "Place ID from candidates",
      "start": "ISO datetime",
      "end": "ISO datetime",
      "estimatedCostUsd": "integer",
      "why": "one-line explanation (max 120 chars)",
      "travelToNext": {
        "mode": "walk | transit | taxi",
        "minutes": "integer"
      }
    }
  ]
}
```

## Rules
1. **Surgical fixes only:** Change only the stops that failed validation. Keep working stops exactly as they were.
2. **Reference only candidate Place IDs:** Never invent venues.
3. **Fix the specific errors:**
   - `venue_not_found` / `not_operational`: Replace with a different candidate of the same type
   - `not_open`: Adjust timing or replace the venue
   - `over_budget`: Replace expensive stops with cheaper candidates or reduce estimated costs
   - `travel_too_far`: Replace distant venues with closer candidates or reorder stops
   - `wrong_stop_type`: Replace with the correct stop type
4. **Maintain chronological order:** Stops must still be in time order
5. **Preserve the option's theme and vibe:** The repaired option should still feel cohesive
6. **Last stop has no travel:** `travelToNext` must be `null` for the last stop only

## Example

**Original option (FAILED):**
```json
{
  "theme": "Cocktails and Italian",
  "stops": [
    {
      "placeId": "ChIJ_closed",
      "start": "2026-10-10T18:00:00Z",
      "end": "2026-10-10T19:30:00Z",
      "estimatedCostUsd": 60,
      "why": "Craft cocktails in a speakeasy vibe",
      "travelToNext": { "mode": "walk", "minutes": 10 }
    },
    {
      "placeId": "ChIJ_good",
      "start": "2026-10-10T19:45:00Z",
      "end": "2026-10-10T21:45:00Z",
      "estimatedCostUsd": 90,
      "why": "Classic red-sauce Italian in the Village",
      "travelToNext": null
    }
  ]
}
```

**Errors:**
- Stop 0: `not_operational` (place is permanently closed)

**Available candidates:** ChIJ_alt (drinks spot, operational, $$, same area)

**Repaired output:**
```json
{
  "theme": "Cocktails and Italian",
  "stops": [
    {
      "placeId": "ChIJ_alt",
      "start": "2026-10-10T18:00:00Z",
      "end": "2026-10-10T19:30:00Z",
      "estimatedCostUsd": 60,
      "why": "Inventive cocktails with a cozy neighborhood feel",
      "travelToNext": { "mode": "walk", "minutes": 10 }
    },
    {
      "placeId": "ChIJ_good",
      "start": "2026-10-10T19:45:00Z",
      "end": "2026-10-10T21:45:00Z",
      "estimatedCostUsd": 90,
      "why": "Classic red-sauce Italian in the Village",
      "travelToNext": null
    }
  ]
}
```

## Instructions
- Be precise: only fix what's broken
- Maintain the original vibe and flow where possible
- If no suitable candidate exists for a broken stop, prefer dropping the stop over inventing one (reduce stops to minimum 2)
- Adjust timing if needed to accommodate replacements
- Update the theme only if the changes significantly alter the option's character
